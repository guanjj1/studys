# Docker 命名卷（Named Volume）与本地卷（Bind Mount）区别

在 Docker 中，持久化数据主要有两种方式：

- **命名卷（Named Volume）**：由 Docker 管理，通过名称引用。
- **本地卷 / 绑定挂载（Bind Mount）**：把宿主机上的任意目录或文件挂载到容器内。

> 严格来说，“本地卷”常指 **Bind Mount**，而“命名卷”是 Docker Volume 的一种。两者在使用方式、生命周期、权限管理上有明显差异。

---

## 一、语法对比

### 命名卷

```yaml
services:
  jenkins:
    volumes:
      - jenkins_home:/var/jenkins_home   # 命名卷

volumes:
  jenkins_home:                          # 顶层声明
```

### 绑定挂载（本地卷）

```yaml
services:
  jenkins:
    volumes:
      - /srv/jenkins_home:/var/jenkins_home   # 宿主机绝对路径
      # 或使用相对路径
      - ./jenkins_home:/var/jenkins_home
```

### 匿名卷

```yaml
services:
  jenkins:
    volumes:
      - /var/jenkins_home   # 只写容器内路径，Docker 自动生成随机名称
```

---

## 二、核心区别

| 对比项           | 命名卷（Named Volume）                          | 本地卷 / 绑定挂载（Bind Mount）            |
| ---------------- | ----------------------------------------------- | ------------------------------------------ |
| **管理方**       | Docker 管理                                     | 用户/宿主机文件系统管理                    |
| **存储位置**     | `/var/lib/docker/volumes/<卷名>/_data`（Linux） | 宿主机任意指定路径，如 `/srv/jenkins_home` |
| **引用方式**     | 卷名，如 `jenkins_home`                         | 宿主机路径，如 `/srv/jenkins_home`         |
| **生命周期**     | 独立于容器，容器删除后仍存在                    | 目录由用户维护，容器删除不影响             |
| **可移植性**     | 跨容器、跨 Compose 项目可复用                   | 依赖宿主机路径，换机器需同步目录           |
| **权限控制**     | Docker 自动处理，初始权限来自镜像               | 完全由宿主机目录权限决定                   |
| **直接访问**     | 不直观，需进入 `/var/lib/docker/volumes/`       | 可直接用文件管理器、编辑器访问             |
| **备份迁移**     | 需用临时容器打包，或 `docker volume` 命令       | 直接 `tar`、`rsync` 宿主机目录即可         |
| **性能**         | Linux 上性能好；Mac/Windows 上优于绑定挂载      | Linux 上接近；Mac/Windows 有文件同步开销   |
| **安全隔离**     | 较好，不暴露宿主机路径                          | 可能挂载敏感目录，风险较高                 |
| **Compose 声明** | 需要顶层 `volumes:` 声明                        | 无需顶层声明，直接写路径                   |

## 三、存储位置与查看

### 命名卷

```bash
# 列出所有命名卷
docker volume ls

# 查看卷详情，包括挂载点
docker volume inspect jenkins_home
```

输出示例：

```json

    "Name": "jenkins_home",
    "Options": null,
    "Scope": "local"
  }
]
```

### 绑定挂载

直接查看宿主机目录：

```bash
ls -la /srv/jenkins_home
```

## 四、生命周期与管理

### 命名卷

```bash
# 创建
docker volume create jenkins_home

# 删除（需先停止使用它的容器）
docker volume rm jenkins_home

# 删除未被使用的卷
docker volume prune
```

- 容器删除时，命名卷**默认保留**。
- `docker compose down` 默认**不删除**命名卷。
- `docker compose down -v` 会删除 Compose 中声明的命名卷。

### 绑定挂载

- 目录完全由用户管理。
- 容器删除、重建，目录内容不受影响。
- 删除数据需手动 `rm -rf /srv/jenkins_home`。

---

## 五、权限与所有权

### 命名卷

- 首次挂载到非空目录时，Docker 会把镜像中该目录的内容复制到卷中，并保留权限。
- Jenkins 官方镜像内 `jenkins` 用户 uid=1000，命名卷初始权限通常正确。
- 一般无需手动 `chown`。

### 绑定挂载

- 宿主机目录权限直接映射到容器内。
- 若宿主机目录属主不是 uid=1000，容器内 Jenkins 可能无法写入。
- 常需要：

```bash
sudo mkdir -p /srv/jenkins_home
sudo chown -R 1000:1000 /srv/jenkins_home
```

## 六、备份与迁移

### 命名卷备份

```bash
docker run --rm \
  -v jenkins_home:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/jenkins_home.tar.gz -C /data .
```

### 命名卷恢复

```bash
docker run --rm \
  -v jenkins_home:/data \
  -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/jenkins_home.tar.gz -C /data"
```

### 绑定挂载备份

```bash
tar czf jenkins_home.tar.gz -C /srv/jenkins_home .
```

### 绑定挂载恢复

```bash
sudo rm -rf /srv/jenkins_home/*
sudo tar xzf jenkins_home.tar.gz -C /srv/jenkins_home
sudo chown -R 1000:1000 /srv/jenkins_home
```

## 七、性能差异

| 平台    | 命名卷                         | 绑定挂载                         |
| ------- | ------------------------------ | -------------------------------- |
| Linux   | 性能好，直接使用宿主机文件系统 | 性能接近，但受宿主机文件系统影响 |
| macOS   | 性能较好，数据在 Docker VM 内  | 有文件同步开销，大量小文件时较慢 |
| Windows | 性能较好                       | 跨文件系统时性能较差             |

> 在 Mac / Windows 的 Docker Desktop 上，命名卷通常比绑定挂载更快，因为少了宿主机与虚拟机之间的文件同步。

---

## 八、适用场景

### 推荐使用命名卷

- 数据库数据目录（MySQL、PostgreSQL）
- Jenkins 主目录
- 需要 Docker 统一管理、跨容器复用
- 不希望关心宿主机具体路径
- 生产环境，追求可移植性与权限一致性

### 推荐使用绑定挂载

- 开发环境，需要实时修改配置文件
- 挂载源代码目录到容器
- 挂载 `/var/run/docker.sock`
- 需要直接用宿主机工具查看、编辑数据
- 挂载宿主机系统文件，如 `/etc/localtime`

---

## 九、Jenkins 场景选择建议

| 需求                       | 推荐方式                                           |
| -------------------------- | -------------------------------------------------- |
| 生产环境，长期稳定运行     | **命名卷** `jenkins_home:/var/jenkins_home`        |
| 开发测试，方便直接查看数据 | **绑定挂载** `/srv/jenkins_home:/var/jenkins_home` |
| 需要备份迁移到其他机器     | 两者均可，命名卷需用临时容器打包                   |
| 多容器共享 Jenkins 数据    | 命名卷更合适                                       |
| 需要挂载 Docker 套接字     | 绑定挂载 `/var/run/docker.sock`                    |

## 十一、一句话总结

- **命名卷**：Docker 托管，省心、可移植、权限统一，适合生产持久化。
- **绑定挂载**：宿主机目录直连，直观、易编辑，适合开发和特殊挂载。
- 两者可以混合使用，例如 Jenkins 数据用命名卷，`docker.sock` 用绑定挂载。


## compose网络
同一个 Compose 文件里多个容器，不需要提前创建网络。
顶层定义一次 networks: netfgbox:，然后多个 service 都引用它就行。

```yaml
services:
  web:
    networks:
      - netfgbox

  api:
    networks:
      - netfgbox

  db:
    networks:
      - netfgbox

networks:
  netfgbox:
    name: netfgbox #可选 
```

多个 Compose 项目之间共用网络才需要提前创建
如果只有一个 Compose 文件，多个容器，不用提前创建。

如果是两个不同的 Compose 项目要互通，才需要：

```shell
docker network create netfgbox
```
然后两边都写：
```yaml
networks:
  netfgbox:
    external: true
```
