 2.使用docker的环境替代系统的环境

参考（https://www.thegeekdiary.com/how-to-configure-docker-to-use-proxy/）
```shell
vim  /etc/systemd/system/docker.service.d/http-proxy.conf
# 如果没有这个文件就直接在文件中输入以下进行保存，创建docker.service.d文件夹后再新建文件

[Service]
Environment="HTTP_PROXY=http://xx.xxx.xx.xx:xxxx"
Environment="HTTPS_PROXY=http://xx.xxx.xx.xx:xxx"
```
 这里配置的是你的堡垒机的ip地址和端口，例如我是本身虚拟机为192.168.101.21，堡垒机为192.168.101.1，所有的虚机机的http及https都通过192.168.101.1的3128端口进行转发（通过squid设置后的代理服务器的ip端口），就配置为如下：
```shell
[Service]
Environment="HTTP_PROXY=http://192.168.3.26:3128"
Environment="HTTPS_PROXY=http://192.168.3.26:3128"

#重启docker
systemctl daemon-reload 
systemctl restart docker
```
### 方式2（本机通过代理服务器上网成功，docker pull失败，此时按方式1设置，可成功）
#### 先将可访问外网的服务器设置为代理服务器
- 1.使用 squid <https://squid.diladele.com/> 安装后默认会启动，默认代理：本机ip：3128
- 2.客户端设置代理 ，debian为例

<https://blog.csdn.net/qq_42704442/article/details/127746279>\
<https://zhuanlan.zhihu.com/p/690804096>\
<https://worktile.com/kb/ask/1173137.html>
```shell
# 测试代理服务器是否设置成功
curl --connect-timeout 2 -x 192.168.3.26:3128 https://www.baidu.com/

#设置代理
nano /etc/profile
#添加如下
export http_proxy=http://192.168.3.26:3128
export https_proxy=http://192.168.3.26:3128
#生效
source /etc/profile

#或
nano /etc/environment

http_proxy=http://<proxy_address>:<proxy_port>
https_proxy=http://<proxy_address>:<proxy_port>
ftp_proxy=http://<proxy_address>:<proxy_port>

```
