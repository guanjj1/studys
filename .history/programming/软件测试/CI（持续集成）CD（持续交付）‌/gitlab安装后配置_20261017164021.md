## 1. 启动与初始访问

```bash
docker compose up -d
```

查看容器状态：

```bash
docker ps
```

获取初始 root 密码：

```bash
docker exec -it gitlab grep 'Password:' /etc/gitlab/initial_root_password
```

访问：

```text
http://服务器IP
```

或配置 HTTPS 后访问：

```text
https://gitlab.example.com
```

首次登录后应立即修改 root 密码。

---

## 2. HTTPS 配置

将 `external_url` 改为 HTTPS 地址：

```ruby
external_url 'https://gitlab.example.com'
```

将证书文件放入挂载目录，例如：

```text
config/ssl/gitlab.example.com.crt
config/ssl/gitlab.example.com.key
```

在 `gitlab.rb` 中指定证书路径：

```ruby
nginx['ssl_certificate'] = "/etc/gitlab/ssl/gitlab.example.com.crt"
nginx['ssl_certificate_key'] = "/etc/gitlab/ssl/gitlab.example.com.key"
```

修改后执行：

```bash
docker exec -it gitlab gitlab-ctl reconfigure
```

若使用 Let's Encrypt：

```ruby
letsencrypt['enable'] = true
```

前提是域名已解析，且 80 端口可从外网访问。

## 3. 项目创建与代码推送

建议按团队建立 Group，项目统一设为 Private。

创建项目后推送代码：

```bash
git init
git remote add origin https://gitlab.example.com/group/project.git
git add .
git commit -m "init"
git push -u origin main
```

使用 PAT 时，注意令牌作用域：

- `read_repository`
- `write_repository`
- `api`

---

## 4. 项目导入与迁移

从旧 GitLab 迁移时，可使用完整备份恢复：

```bash
gitlab-backup restore BACKUP=备份文件名
```

恢复前通常需要停止写入服务：

```bash
gitlab-ctl stop unicorn
gitlab-ctl stop sidekiq
gitlab-backup restore BACKUP=xxx
gitlab-ctl reconfigure
gitlab-ctl start
```

注意：恢复对象是完整实例备份，不是单个项目导出。

---

## 5. CI/CD 基础接入

在项目根目录添加 `.gitlab-ci.yml`，典型阶段：

```yaml
stages:
  - build
  - test
  - deploy
```

注册 GitLab Runner 后，将 Runner 绑定到项目或 Group。

CI/CD 变量、Runner Token 等敏感信息应通过 GitLab 的 CI/CD Variables 管理，避免写入仓库。

---

## 6. 常用运维命令

```bash
# 重新加载配置
gitlab-ctl reconfigure

# 查看状态
gitlab-ctl status

# 重启
gitlab-ctl restart

# 创建备份
gitlab-backup create

# Docker 环境下执行
docker exec -it gitlab gitlab-ctl reconfigure
```

---

## 7. 注意事项

- 修改 `/etc/gitlab/gitlab.rb` 后必须执行 `gitlab-ctl reconfigure`。
- 部署前确认 80/443/22 端口未被占用。
- 防火墙和安全组需放行对应端口。
- 邮件通知需额外配置 SMTP，否则注册确认、密码重置等功能可能不可用。
- 备份保留时间只是清理策略，仍需定期验证备份可恢复。
- 生产环境建议固定 GitLab 镜像版本，避免 `latest` 带来的升级不确定性。
