# Jenkins (`jenkins/jenkins`) Docker 安装使用完整教程

## 一、背景与镜像选择

### 1.1 为什么不再使用 `jenkinsci/blueocean`

`jenkinsci/blueocean` 镜像已停止维护，基于 Alpine 3.16.2 旧系统，内置 Jenkins 2.346.3，存在未修复的严重安全漏洞。官方推荐迁移到标准的 `jenkins/jenkins` 镜像。

### 1.2 `jenkins/jenkins` 镜像标签选择

| 标签                        | 适用场景     | 说明                           |
| --------------------------- | ------------ | ------------------------------ |
| `jenkins/jenkins:lts`       | 通用生产     | 最新 LTS 版本                  |
| `jenkins/jenkins:lts-jdk17` | **推荐生产** | LTS + JDK 17，兼容性与性能平衡 |
| `jenkins/jenkins:lts-jdk21` | 新项目       | LTS + JDK 21，支持最新特性     |
| `jenkins/jenkins:latest`    | 仅测试/尝鲜  | Weekly 版本，稳定性风险高      |

生产环境优先选择 LTS 版本，每 12 周发布一次，官方提供至少 1 年的安全更新与 bug 修复。**推荐使用 `jenkins/jenkins:lts-jdk17`**，因为 Jenkins 2.479.1 起已要求 Java 17，Java 11 镜像已退役。

## 二、安装部署

### 2.1 方式一：Docker Run（快速启动）

**步骤 1：拉取镜像**

```bash
docker pull jenkins/jenkins:lts-jdk17
```

**步骤 2：创建数据目录并设置权限**

容器内 Jenkins 默认以 uid=1000 运行，需提前修正宿主机目录权限：

```bash
sudo mkdir -p /srv/jenkins_home
sudo chown -R 1000:1000 /srv/jenkins_home
```

**步骤 3：启动容器**

```bash
docker run -d --name jenkins \
  -p 8080:8080 -p 50000:50000 \
  -v /srv/jenkins_home:/var/jenkins_home \
  -e TZ=Asia/Shanghai \
  -e JAVA_OPTS="-Duser.timezone=Asia/Shanghai -Xmx2g -Xms512m" \
  --restart unless-stopped \
  jenkins/jenkins:lts-jdk17
```

> **端口说明**：8080 为 Web UI，50000 为 Agent 通信端口。
> **数据持久化**：`-v /srv/jenkins_home:/var/jenkins_home` 将数据映射到宿主机，避免容器重建导致数据丢失。

### 2.2 方式二：Docker Compose（推荐，便于管理）

创建 `docker-compose.yml`：

```yaml
# Docker Compose 配置文件版本（Compose V2 中可省略此字段）
version: "3.8"

services:
  # 定义 Jenkins 服务
  jenkins:
    # 使用的镜像：Jenkins LTS 版本，内置 JDK 17
    image: jenkins/jenkins:lts-jdk17
    # 容器名称，方便后续 docker 命令操作
    container_name: jenkins
    # 重启策略：除非手动停止，否则容器退出时自动重启
    restart: unless-stopped
    # 端口映射：宿主机端口:容器端口
    ports:
      - "8080:8080"   # Jenkins Web UI 访问端口
      - "50000:50000" # Jenkins Agent 通信端口（JNLP）
    # 数据卷挂载
    volumes:
      # 命名卷，持久化 Jenkins 全部数据（作业、插件、配置、凭据等）
      - jenkins_home:/var/jenkins_home
      # 挂载宿主机 Docker 套接字，使容器内可直接调用宿主机 Docker（可选）
      # 注意：挂载 docker.sock 会让容器拥有宿主机 Docker 的完整控制权，存在安全风险
      - /var/run/docker.sock:/var/run/docker.sock
    # 环境变量配置
    environment:
      # 设置容器系统时区为上海
      - TZ=Asia/Shanghai
      # JVM 启动参数：设置 Java 时区、最大堆 2g、初始堆 512m
      # 建议用引号包裹，避免 YAML 解析歧义
      - "JAVA_OPTS=-Duser.timezone=Asia/Shanghai -Xmx2g -Xms512m"
    networks:
      - netjenkins

# 命名卷声明
volumes:
# jenkins_home 命名卷：使用 docker volume ls 可查看，备份时可通过临时容器打包该卷。
  # 声明 jenkins_home 卷，由 Docker 管理，默认位于 /var/lib/docker/volumes/
  jenkins_home:

networks: 
  netjenkins:
```

# `/var/run/docker.sock` 挂载场景详解

## 一、什么是 `docker.sock` 挂载

`/var/run/docker.sock` 是 Docker 守护进程（dockerd）的 Unix 套接字。将宿主机的该文件挂载到容器内：

```yaml
volumes:
  - /var/run/docker.sock:/var/run/docker.sock
```

容器内的 Docker CLI 就能通过这个套接字与**宿主机上的 Docker 守护进程**通信。也就是说，在 Jenkins 容器里执行 `docker build`、`docker run` 等命令，实际是在宿主机上创建镜像和容器，而不是在 Jenkins 容器内部。

---

## 二、典型使用场景

### 1. 在 Jenkins 流水线中构建 Docker 镜像

**场景**：流水线需要将代码构建成 Docker 镜像并推送到镜像仓库。

```groovy
pipeline {
    agent any
    stages {
        stage('Build Image') {
            steps {
                sh 'docker build -t myapp:${BUILD_NUMBER} .'
                sh 'docker push myapp:${BUILD_NUMBER}'
            }
        }
    }
}
```

挂载 `docker.sock` 后，`docker build` 会直接使用宿主机的 Docker 环境，镜像存储在宿主机上，无需在 Jenkins 容器内再运行一个 Docker 守护进程。

### 2. 在流水线中运行容器作为构建/测试环境

**场景**：使用临时容器执行编译、测试，例如：

```bash
docker run --rm -v $PWD:/app -w /app maven:3.9 mvn test
```

这样 Jenkins 容器本身无需安装 Maven、Node 等工具，直接利用 Docker 镜像提供干净环境。

### 3. 使用 Docker Compose 部署服务

**场景**：在 Jenkins 中执行 `docker compose up -d` 部署多容器应用。

```bash
docker compose -f docker-compose.prod.yml up -d
```

挂载 `docker.sock` 后，Compose 命令可以在 Jenkins 容器内正常操作宿主机 Docker。

### 4. 动态创建 Jenkins Agent

**场景**：配合 Jenkins 的 **Docker Plugin** 或 **Kubernetes Plugin**，按需启动 Agent 容器。

Docker Plugin 需要与 Docker 守护进程通信来创建、启动、停止 Agent 容器，因此必须挂载 `docker.sock`。

### 5. 执行 Docker 清理与运维命令

**场景**：定期清理无用镜像、容器、卷。

```bash
docker system prune -af
docker volume prune -f
```

## 三、工作原理简述

```text
+-------------------+        /var/run/docker.sock        +-------------------+
|  Jenkins 容器      |  <--------------------------------> |  宿主机 dockerd   |
|  (docker CLI)     |         Unix Socket 通信            |  (Docker 守护进程) |
+-------------------+                                     +-------------------+
                                                                  |
                                                                  v
                                                          +-------------------+
                                                          |  宿主机上的容器    |
                                                          |  和镜像            |
                                                          +-------------------+
```

- 容器内**必须有 Docker CLI**（`docker` 命令），否则挂载套接字也没用。
- Jenkins 官方镜像默认**不包含** Docker CLI，需要额外安装或挂载宿主机的 Docker 二进制文件。

## 四、安全风险与注意事项

| 风险               | 说明                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------- |
| **等同 root 权限** | 能访问 `docker.sock` 就相当于拥有宿主机 root 权限，可启动特权容器挂载宿主机根目录，实现容器逃逸。 |
| **越权操作**       | Jenkins 任务可能误删宿主机上的其他容器、镜像或卷。                                                |
| **多租户风险**     | 如果 Jenkins 对多个团队开放，挂载 `docker.sock` 会导致严重的安全隔离问题。                        |

**建议**：
- 仅在**受信任的单一团队**内部使用。
- 不要将 Jenkins 直接暴露到公网。
- 尽量使用**只读挂载**？实际上 `docker.sock` 无法只读，必须可写。
- 考虑使用 **Rootless Docker** 或 **Podman** 降低风险。

## 五、替代方案

| 方案                        | 说明                                        | 优缺点                               |
| --------------------------- | ------------------------------------------- | ------------------------------------ |
| **Docker-in-Docker (DinD)** | 在容器内运行独立 dockerd，需 `--privileged` | 隔离性好，但性能差、特权模式仍有风险 |
| **Kaniko**                  | 无需 Docker 守护进程构建镜像                | 安全，但仅支持构建，不能运行容器     |
| **Buildah / Podman**        | 无守护进程构建镜像                          | 安全，适合构建场景                   |
| **远程 Docker + TLS**       | 通过 TCP + TLS 连接远程 Docker 守护进程     | 无需挂载套接字，但需配置证书         |
| **Kubernetes Agent**        | 使用 Kubernetes 动态提供 Agent              | 云原生方案，适合大规模               |

## 六、完整配置示例（含权限处理）

仅挂载 `docker.sock` 往往不够，还需解决 **Docker CLI 缺失** 和 **套接字权限** 问题。

### 6.1 挂载 Docker CLI 和套接字

```yaml
services:
  jenkins:
    image: jenkins/jenkins:lts-jdk17
    container_name: jenkins
    restart: unless-stopped
    ports:
      - "8080:8080"
      - "50000:50000"
    volumes:
      - jenkins_home:/var/jenkins_home
      # 挂载宿主机 Docker 套接字
      - /var/run/docker.sock:/var/run/docker.sock
      # 挂载宿主机 Docker CLI 二进制文件（避免容器内安装）
      - /usr/bin/docker:/usr/bin/docker:ro
      # 如果 Docker CLI 依赖其他库，可一并挂载（视宿主机发行版而定）
      # - /usr/lib/x86_64-linux-gnu/libltdl.so.7:/usr/lib/x86_64-linux-gnu/libltdl.so.7:ro
    environment:
      - TZ=Asia/Shanghai
    # 将容器内 jenkins 用户加入宿主机 docker 组，使其有权访问 docker.sock
    group_add:
      - "999"   # 替换为宿主机 docker 组的 GID，通过 `getent group docker` 查看
```

### 6.2 查看宿主机 docker 组 GID

```bash
getent group docker
# 输出示例：docker:x:999:
```

将 `999` 填入 `group_add`。

### 6.3 验证

进入容器执行：

```bash
docker exec -it jenkins bash
docker ps
```

若能正常列出宿主机容器，则配置成功。

| 场景                         | 建议                                                     |
| ---------------------------- | -------------------------------------------------------- |
| 内部单一团队，Jenkins 不对外 | 可以使用 `docker.sock` 挂载，简单高效                    |

启动：

## 五、从旧镜像迁移数据

如果你有基于 `jenkinsci/blueocean` 的现有实例，可参照以下步骤迁移：

### 5.1 备份旧数据

```bash
# 方法一：从旧容器拷贝
docker cp <旧容器名>:/var/jenkins_home /backup/jenkins_home_backup

# 方法二：若使用命名卷
docker run --rm -v jenkins_old:/var/jenkins_home -v $(pwd):/backup \
  alpine tar czf /backup/jenkins_home.tar.gz -C /var/jenkins_home .
```

### 5.2 恢复数据到新容器

```bash
# 停止新容器
docker stop jenkins

# 清空新数据目录并恢复
sudo rm -rf /srv/jenkins_home/*
sudo cp -a /backup/jenkins_home_backup/. /srv/jenkins_home/
sudo chown -R 1000:1000 /srv/jenkins_home

# 重启
docker start jenkins
```

> **关键**：凭据文件（`credentials.xml`）依赖 `secrets/secret.key`，必须一并迁移，否则凭据将失效。建议迁移前检查插件兼容性，旧镜像（Jenkins 2.346.3）的插件可能不兼容新版本。

## 六、性能调优

### 6.1 JVM 内存参数

通过 `JAVA_OPTS` 环境变量调整 JVM 堆内存：

```bash
-e JAVA_OPTS="-Xms2g -Xmx2g -XX:MaxMetaspaceSize=512m -Dfile.encoding=UTF-8"
```

建议将 `-Xms` 与 `-Xmx` 设为相同值（通常为物理内存的 1/2），避免运行期扩缩堆带来的性能抖动。

对于 Java 17+ 环境，官方推荐使用百分比方式配置：

```bash
-e JAVA_OPTS="-XX:+UseG1GC -XX:MaxRAMPercentage=60.0 -XX:InitialRAMPercentage=20.0"
```

### 6.2 时区设置

```bash
-e TZ=Asia/Shanghai
-e JAVA_OPTS="-Duser.timezone=Asia/Shanghai"
```

## 八、常见问题

**Q：容器启动后立即退出？**
A：检查数据目录权限是否为 uid=1000。使用 `sudo chown -R 1000:1000 /srv/jenkins_home` 修正。

**Q：插件下载极慢或失败？**
A：更换插件更新站点为清华镜像（见 4.1 节），或在宿主机 `/srv/jenkins_home/updates/default.json` 中替换下载地址。

**Q：如何升级 Jenkins？**
A：拉取新标签镜像，停止旧容器（保留数据卷），用相同挂载参数启动新容器即可。升级前务必备份 `jenkins_home`。

**Q：能否在容器内构建 Docker 镜像？**
A：可以。启动时挂载 `-v /var/run/docker.sock:/var/run/docker.sock`，或使用 Docker-in-Docker 方案。
